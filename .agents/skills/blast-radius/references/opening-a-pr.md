# Opening a PR

Check the target branch and any existing PR. Read the final diff and follow the repository's conventions for branches, commits, and attribution.

Keep the title specific. Give the reviewer a short briefing covering the reason for the change, the behavior that changed, any meaningful tradeoff or risk, and the checks actually run. Include an output, screenshot, or artifact link when it substantiates a claim. Mention verification gaps that affect the merge decision. Flag lasting project instruction changes and their evidence.

Open or update the PR when the work is ready and the repository workflow calls for it. Leave merge and auto-merge to the authorization rules in `AGENTS.md`.
