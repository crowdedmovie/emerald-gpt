---
name: teach
description: "Teach a person how a codebase, feature, or change works and why it is shaped that way. Use for guided explanations during onboarding, debugging, or PR review."
---

1. Start from what the user needs to understand to review, change, or debug the work.
2. Apply the `how` method in this session to trace the behavior. Apply `why` when historical decisions would help explain it. Preserve the confidence of any historical claim.
3. Start with a plain definition tied to the concrete case. Walk through one real example or execution path, then cover the edge cases that matter. Use code references or a diagram when they clarify the mechanism.
4. Match the depth to the question. Leave the repository untouched.
